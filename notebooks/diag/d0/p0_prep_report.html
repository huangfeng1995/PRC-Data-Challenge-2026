两侧 MVT 语义不同但各自自洽：DEP 的 MVT 是起飞（自 ADEP 机场），ARR 的 MVT 是落地（其 ADES 机场）。 ARR 侧可用 (BLOCK − MVT) 交叉验证，中位 +478s 为正 → 确为落地时刻 ✓。 ranking ARR 689,534 行中 DEP 344,841 / ARR 344,693。

核查 6 · 结论

判定 (a)：MVT_TIME_UTC_mvt 在 ranking DEP 是【真实的未来起飞时刻】。

  1. 绝不能当特征（R7 已写进 P0 脚本）。它发生在预测时点之后， 99.95% 晚于 AOBT，中位差 978s，是真实运营结果而非计划值（与 SCHED 仅 0.007% 相等）。
  2. 但不构成「直接答案泄漏」。精确恒等式是 TAXITIME = MVT − BLOCK， 而 ranking DEP 已把 BLOCK 整列抽空（0.00%）；且 AOBT_3_flt 与 BLOCK 并非同一字段 （相等仅 0.64%，|差|p95=715s），所以 (MVT − AOBT) 只是近似 ——corr=0.556、RMSE=411s，劣于现有模型。
  3. 需要重新理解的点：BLOCK 才是答案锚点而非 AOBT。这意味着「已知 AOBT」并不等于 「已知 BLOCK」，用 AOBT 近似 BLOCK 会引入 715s(p95) 的噪声。本项目此前以 AOBT 作为推出参照的 做法在语义上是「近似锚点」，这一偏差应记录在案。

2.2 CAT 超时保护（v15 教训的修复）

v15 事故：cat123 / cat2024 跑完训练后在 save_model 之前被 >20min 保护 break，模型从未落盘 → 磁盘上只剩 cat_seed42。
本脚本两条规则：① save_model 是 return 之前的最后一步，任何退出路径都先落盘；② 软截止优雅降级，返回已训部分而非 break 掉进程。
